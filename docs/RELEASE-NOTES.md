## 先看目录，点开才要密码

这个版本的压缩包预览器支持**加密压缩包**。打开一个带密码的包不再需要先输口令 —— 目录、文件名、大小照常显示（ZIP 的中央目录本身不加密），加密的条目挂一把橙色锁。只有当你真的要**双击打开某个文件或解压**时，才会弹出口令框。

### 新增

- **加密条目显示锁图标**：一眼看出包里哪些文件加了密，哪些是明文
- **口令框按需弹出**：双击加密文件时才问，同一会话内只问一次；口令错了提示重输，不会静默失败
- **打开包本身不需要口令**：列目录、展开文件夹、看大小和日期全都不受阻

### 修复

- **加密包会让程序永久卡死**。这是 v1.3 的一个真实缺陷：解压走 bsdtar，它碰到加密条目会去读 `/dev/tty` 要口令，而 GUI 进程没有终端，于是无限等待 —— 表现出来就是双击后一直转圈，没有任何提示。现在永远显式传 `--passphrase`，没有口令时喂一个哨兵值让它立刻失败，再由上层弹出输入框
- **口令错误曾被当成解压成功**。bsdtar 在口令错误时**退出码依然是 0**，只在 stderr 写 `Incorrect passphrase`，于是会留下一堆 0 字节的坏文件。现在改成看 stderr 判定，并且错误口令产生的残片会立即删除，避免下次把垃圾当正常文件打开

### 变更

- **缓存改为零留存**：关闭窗口或退出应用时，`~/Library/Caches/com.local.archivepreview/preview/` 整个删除，不再用「清理一天前的缓存」这种策略。代价是：如果你双击打开的文件还在「预览」里开着，关掉本程序后那边会提示文件已删除 —— 需要留存的文件请走「解压到…」

### 已知限制

- **一个包只支持一个口令**。ZIP 规范允许每个条目用不同密码，这种包目前只会解出第一段，其余报密码错
- **WinZip AES-256 加密的 zip 未经验证**。传统 ZipCrypto 已实测通过，AES 那套在开发机上没能造出样本
- 不会尝试任何弱口令或字典破解，只认你手动输入的密码

### 下载

| 文件 | 说明 |
|---|---|
| **`ArchivePreview-<版本>.dmg`** | 推荐。打开后把「压缩包预览器」拖到 Applications 文件夹 |
| `ArchivePreview-<版本>.zip` | 备用。解压后把 `压缩包预览器.app` 拖进「应用程序」 |

两个包都是**通用二进制**，Apple Silicon 和 Intel Mac 都能直接跑，无需 Rosetta。

因为是本地临时签名（ad-hoc），首次打开需要**右键点图标 → 打开 → 再点「打开」**，之后双击就正常了。这是没做 Apple 开发者公证的必然结果。

### 系统要求

macOS 13 或更新。无第三方依赖 —— rar / 7z / 加密 zip 的解码都复用系统自带的 libarchive。

安装后可以在应用的「设置」里一键接管 zip / tar / rar / 7z 等 8 种格式的双击行为，也可以随时还原给系统「归档实用工具」。

从源码构建：

git clone https://github.com/HarmonyHI/ArchivePreview.git
